怎么判断 AI 移植的两万五千行代码能不能用？

车传凯 / 2026-02 专题

网页上一段 2 + 3，进了浏览器以后，要先变成语法树，再变成引擎能执行的字节码。Ladybird 团队打算把这条流水线从 C++ 搬到 Rust。一个挺妙的地方是，新旧两套都能吃同一段脚本，中间交出来的东西也能摊开比。

开发者 Andreas Kling 用两个编程助手帮忙做翻译，自己决定先搬哪块、接口长什么样。两周左右，写出了约两万五千行 Rust。他给自己定了一条有点较真的规矩。只要喂进去的是同一段代码，连两边吐出的字节码都要逐字节相同。这样，哪怕网页上碰巧都显示了 5，编译过程走岔了也藏不住。

原文列了 52,898 个 JavaScript 规范测试和 12,461 个项目测试，两套都没发现回归。作者还让新旧实现同时处理浏览网页时遇到的脚本，及时对比输出。这种办法比「点开首页，页面看起来没问题」多照亮了不少角落。

当然，旧实现要是本来就有个错，新实现也可能原样学过去。先把兼容性对齐，再来改写得别扭的地方，我觉得这个顺序很适合这种有老代码可以对照的任务。
