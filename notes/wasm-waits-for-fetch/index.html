网页去拿文件时，Wasm 能在原地等一下吗？

车传凯 / 2026-06 专题

一段老 C 程序要读模型文件，通常先调用读取函数，再检查文件头，最后解析内容。这三行顺着看很自然。把它搬进浏览器，中间却卡了一下。假设文件在网上，JavaScript 调用 fetch 后先拿到一个 Promise，真正的数据还在路上。下一行凭什么立刻开始检查文件头呢？

Safari 27 测试版支持了 WebAssembly 的 JavaScript Promise Integration，简称 JSPI。在需要等待的调用上，浏览器可以先挂起这段 Wasm 执行。文件拿到了，再从刚才停住的地方继续。这样，原来好几层函数之间传递的仍然是它们熟悉的结果，外面负责对接异步操作即可。等待期间浏览器还有机会响应点击和滚动，页面不用陪着这次请求一起停住。

我觉得用两种不同的卡顿来记会更清楚。等文件时没有东西可算，挂起正合适。拿到文件后，假设解析要一口气做几百万次运算，这一段仍然会占用执行它的线程。JSPI 帮忙过的是等待这一关。真想让重计算也不影响界面，还得安排到合适的线程上。
