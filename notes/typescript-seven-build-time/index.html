TypeScript 快了十倍，省下的是哪段等待？

微软在 TypeScript 7 的发布文章里摆了张表。拿 VS Code 的代码库做完整构建，旧版用了 125.7 秒，新版用了 10.6 秒。两分钟和十来秒的区别挺直观。前者够起身倒杯水，后者可能还没想好要不要起身，结果已经出来了。

变化发生在开发工具这一边。团队用 Go 移植了编译器，尽量保留原有的类型检查逻辑，再利用原生代码和共享内存多线程来处理大项目。平常敲的还是 TypeScript，运行的依旧可以是 tsc。另一个我觉得更贴近写代码的数字，是他们在同一台机器上打开 VS Code 项目里的一个文件，从开编辑器到看到第一处报错，等待时间从大约 17.5 秒降到了 1.3 秒以内。

怎么知道自己的项目能省几秒？我会把流水线里的类型检查、打包、上传分开看。假如最慢的是上传图片，那编译器再快，整次发布也很难跟着快十倍。至于读者打开网页要等多久，那是浏览器的另一笔账。看完这个表，最有用的动作也许是先给自己那几段命令分别计时。
