Java 给每个小对象省下的那 4 个字节

想象这样一个 Java 类，只放两个字段，分别记一张车票从哪站出发、到哪站下车。把两个字段的大小加起来，离这张票在内存里的实际占用还差一点。HotSpot 也要为对象存一份管理信息，比如它属于哪个类。在堆里新建一百万张车票，这份开销也跟着付一百万次。

JDK 27 在 64 位 HotSpot 上默认使用紧凑对象头。发布说明里的数字很直白，常见对象头原来有 96 位，现在压到 64 位，换成字节就是从 12 到 8。只算一百万份对象头，差额是四百万字节，约 3.8 MiB。代码里那些车票的字段可以照旧写，这项变化发生在虚拟机摆放对象的时候。

这个算术还没回答整段程序能省多少内存。对象通常得按一定边界对齐，头部缩短以后，有些布局会跟着变小，有些尾部会多留出填充。还有一种极端情况，一块很大的字节数组自己也只有一个数组对象头，里面存再多照片像素，也不会按每个像素省四字节。看见堆占用下降的数字，我会想先知道，里面装的是成片的数据，还是密密麻麻的小对象。
